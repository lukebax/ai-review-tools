# Working on ai-review-tools

Read README.md and the affected component’s README before editing. This repository contains a standalone static map and a browser presentation.
Keep private source libraries and unrelated files out of this public repository.

- Edit map/map-data.json and map/map-template.html; regenerate map/index.html using
  python3 map/build.py. The map lives at /map/; root index.html is the landing page.
- Keep the browser deck and its assets in presentation/. The shared root preview.py serves both components;
  the presentation README documents PDF export. Avoid coupling the map to presentation dependencies.
- Both components are published on GitHub Pages. The user permits URL changes when they
  make the structure clearer; historical URLs are not a requirement. Keep each component
  self-contained and update the landing links and documentation when paths change.
- Keep all required project files versioned. Do not add hidden/private dependencies
  or blanket ignore rules. Use an operating-system temporary directory for inspection output.
- Preserve the precise RAISE source version, task-specific recommendations, identified
  interpretations and attribution. Inspect successor guidance before changing the source baseline.
- When refining content, preserve established task boundaries, implementation qualifications and
  useful independently sourced details. Keep RAISE statements, editorial interpretation and product
  evidence distinct. A citation correction should not erase a supported explanation. Reverse an
  earlier substantive conclusion only when new evidence or a demonstrated error justifies it, and
  record the reason in the change description. Do not repeat completed audits without a new trigger.
- Retain familiar, appropriate scientific and methodological terminology. Add brief contextual
  or parenthetical explanations where a novice may need them; do not globally replace technical
  terms with less precise wording or remove useful distinctions for apparent simplicity.
- Keep the four RAISE technology families distinct in data, filters and explanations.
  Machine Learning is a visual parent for separate Unsupervised and Supervised headings,
  not a merged category. Retain Table 2 terminology separately from the map family.
- Keep the eight-stage scope and separate outside-stage explanations unless the maintainer
  authorises a scope change. A new third recommendation within one cell requires a reviewed
  visual convention; do not silently omit it or choose one category.
- Balanced is the fresh-load default. Any palette change must update cells, diagonal halves,
  key and detail panels consistently. Keep textual recommendations and keyboard access.
- Use python3 map/build.py --check, then browser-test affected map interactions. Keep map
  viewing self-contained: no runtime network dependency, server requirement or external
  workspace paths. A local server is optional for previewing the presentation.
- Preserve the MIT software / CC BY 4.0 content distinction and third-party notices, including
  notices embedded in the distributable HTML.
- Luke reviews requested map updates on GitHub Pages. His standing instruction is to edit and
  rebuild locally, verify the result, commit and push the changed sources and generated HTML,
  then verify the Pages deployment and pull its generated commit with `git pull --ff-only`
  before handing it back for review. A map-update request
  authorises this release workflow unless he explicitly asks for local-only preparation.
  Changing repository visibility or hosting configuration still requires explicit authorisation.

- Pages publication must pass `.github/workflows/pages.yml`: generate/check the PDF from
  the same sources, save generated outputs, then deploy the checked site artifact. Keep
  Pages in Actions mode. Do not bypass this gate with direct branch publishing.
- Actual-map slide images are generated by `presentation/capture_maps.mjs`, including native labels and key.
  `npm run build:pdf` refreshes these captures before export; keep their manifest and PNGs versioned.
- After slide edits run `npm run build:pdf` and `npm run check`; check meaningful visual
  changes in HTML/PDF. `pdf-build.json` records input/output integrity, not a history log.
  Never hand-edit its hashes or treat a stale PDF as a valid fallback.

- Presenter notes are derived from the approved Delivery Script with
  `python3 presentation/sync_notes.py /path/to/delivery-script.md`; use `--check`
  to verify exact passages and cue separation. Do not independently rewrite embedded
  speech or hand-edit approval fingerprints. A changed script structure requires
  reviewed slide boundaries. Keep `showNotes:false` and notes out of the audience PDF.
